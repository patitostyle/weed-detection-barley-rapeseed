# Controlled barley-to-rapeseed evaluation

Reproducibility files for the revised manuscript, complementing the original scripts in the parent repository. This folder contains the spatial partition, paired adaptation subsets, training/evaluation code, reported results, figure sources and retained figure inputs. It does not replace or silently rerun the original experiments.

## Data and model

Dataset: https://doi.org/10.17632/mb4jvxk9dk.1 (see its data licence).

Arrange the image/mask patches under `DATA_ROOT/patches/colza_v2_rgb_nir_re_indices/{images,masks}/`. Source verification/qualitative inference additionally require `DATA_ROOT/patches/cebada_v2_C2_rgb_nir_re_indices/{images,masks}/`. Keep original TIFF filenames. Images have eight channels; mask values are 0=unlabelled, 1=crop, 2=weed and 3=soil. Unlabelled pixels are ignored.

The initialization checkpoint is a separate GitHub Release asset, not an ordinary repository file. See MODEL_CHECKPOINT.md and place it in `models/` before training. The repository package does not contain the raw orthomosaics or all 18 target checkpoints.

## Installation

Use Python 3.11 or a compatible environment. Install a PyTorch build appropriate for the device, then `python -m pip install -r requirements.txt`. The recorded execution versions and GPU are in verification_summary.json. Exact bitwise agreement across hardware/software is not guaranteed. Source code is under the original repository MIT licence; the original dataset licence governs data and image-derived assets.

## Inspect the reported evidence without training

From this folder, run:

```sh
python code/verify_release.py
python code/make_figures.py
```

The verifier uses only the Python standard library. Figure generation uses the archived numerical results and figure arrays; it does not train or evaluate models. Outputs: generated_figures/ (Figures 3, 6, 7, 8 and 9). The manuscript workflow source is `code/make_workflow_revised.py`. Figures 1, 4 and 5 are original author figures and were not regenerated by these new analysis scripts.

## Reproduce training and fixed-test evaluation

In PowerShell, set only the data directory (the defaults for package outputs and checkpoint location are portable):

```powershell
$env:WEED_DATA_DIR = 'C:/path/to/DATA_ROOT'
python code/revision_colza_controlada.py --train
python code/revision_colza_controlada.py --evaluate
```

In bash, use `export WEED_DATA_DIR=/path/to/DATA_ROOT` followed by the same Python commands. Optional: set WEED_BASE_MODEL to another location of the SAME retained checkpoint, and WEED_WORK_DIR to this folder. Do not change weights or test-based settings and still call the run a reproduction.

New runs are written to runs/, separately from reported_results/. Finish all 18 training runs before --evaluate. Existing final test results are not overwritten; incomplete runs require explicit inspection. Do not delete archived evidence to resume a run. The script retains the original experiment settings; only input/output path defaults were adapted for publication. Exact original source is in provenance/.

The 269/57/97-patch spatial partition is fixed. Training subsets of 21/42/63 patches are nested per seed (42/43/44), conditioned on class availability, and paired across full fine-tuning and random initialization. Both strategies use Adam 1e-4, batch 4, weighted cross-entropy [1,3,1.5], maximum 30 epochs, patience 7 and minimum validation F1 improvement 1e-4. No augmentation was used. Final metrics average probabilities over repeated occurrences of each labelled geographic pixel before assigning a class.

## Optional source verification and annotation audit

```sh
python code/check_source_checkpoint.py
python code/export_qualitative.py
python code/auditar_datos_tfm.py
python code/viabilidad_colza.py
```

Source checks and new qualitative arrays go to regenerated/. Raw annotation audit and feasibility reconstruction go to audit_rebuilt/; run the audit before the feasibility script. These steps need the corresponding original data. They do not overwrite the published partition lists. `viabilidad_colza.py` includes simulations of random-patch overlap; these are not recovered historical splits and do not reconstruct the original leakage rate. Avoid using a newly selected partition for comparison with the fixed reported test.

## Interpretation

Direct transfer weed F1 = 0 on the fixed target test. With 63 adaptation patches, full fine-tuning F1 = 0.2924 +/- 0.2406 and scratch = 0.0256 +/- 0.0409. Full fine-tuning wins 3 of 9 paired runs. Repetitions vary both subset and initialization and share one test group; they are not independent field replicates. Earlier random-patch scores are not interchangeable with these results. Source spatial validation used Barley 2 for checkpoint selection. The 0-100 map is a stored prediction-score index, not validated weed density.

## Archived evidence

- reported_results/protocol.json: exact recorded settings.
- reported_results/subset_*.json: all nine adaptation subsets.
- reported_results/*/history.json and complete.json: all 18 runs.
- reported_results/test_results.json: direct baseline and all 18 confusion matrices/metrics.
- target_results.csv: tabular results used for reporting.
- auditoria_datos_tfm.json and viabilidad_colza.json: geometry, annotation counts and feasibility records.
- source_checkpoint_verification.json: re-evaluation of the retained source checkpoint.
- artifacts/: source training log, qualitative arrays and retained score raster array.
- SHA256.json: checksums for all files distributed in this folder.

The manuscript .tex and personal paths/contacts are not included. No code, file or result has been published by merely creating this folder; it must be uploaded by the repository owner.
